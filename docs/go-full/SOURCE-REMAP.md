# Source remapper and exact matcher primitives

Sprint: #148; Story: #31; Story-ID: 7a1175a64d88 (packet 148.3, mechanism only,
no corpus credit)

`tools/go-full/source-remap` is a self-contained Go module with three
primitives and one JSON command. It never runs a program or a compiler; it
adjudicates retained evidence. Wiring it into `product.rb`, receipts and the
recipe adapter registry is the Substrate Integration Owner's seam; which
recipes get which tolerance is Sprint 154 diagnostic policy. Nothing here
changes the existing `diagnostics` or `typecheck-diagnostics` tools.

## Why a separate primitive

A minimal repro against the current `tools/go-full/diagnostics` matcher: one
`// ERROR "undefined: missing"` annotation with the same diagnostic emitted
twice on that line returns `PASS`. That is upstream errorcheck's tolerance
(one annotation consumes every matching diagnostic on its line), not an exact
multiplicity contract. Separately, nothing in Go consumed
`bashy-transpile-map-v1`, so a diagnostic positioned on lowered output could
not be put back on the original source at all.

## 1. Validated original-position remapper

`decodeSourceMap` + `validateSourceMap` build on
`Corpus.valid_source_map?` (`tools/corpus/executor.rb`) and enforce:
schema/kind/front-end identity, `go_digest` against the
actual generated bytes, an origin equal to the first safe relative source
name, exact ordered source-name set, per-source digest,
size and concatenation base, the lowerer's next-nonempty-line `// lower:N`
marker contract (the map must record exactly those generated positions, in
order), and every original line/column recomputed from the recorded byte
offset. Scalars are typed strictly (`0.0` is not an integer). The retained
product map under `tests/corpus/fixtures/source-map` validates, and the same
mutation list the Ruby tests use rejects.

`remapper.remap(file, line, col)` resolves one diagnostic position:

- a position on a registered generated file resolves through the map entry
  recorded for exactly that generated line; the column is carried only when
  it equals the recorded node start (`column_exact`), otherwise the result is
  line-only (`a.go:4`) — a fabricated column is never emitted;
- a position that already names an original file is a claim made by a
  `//line` directive in the lowered output; it is accepted only when the map
  independently records that original line as a lowering target
  (`verified_claim`), so claims are verified rather than trusted;
- a generated line the map does not record, an original line the map does
  not record, and a file no map covers are errors — no nearest-marker guess.

Registration fails closed on ambiguity: two maps for one generated name, a
generated name that is also an original name, one original with two
diagnostic names, one diagnostic name for two originals, or one generated
line with two original positions.

`remapAll` fails closed over a captured stream: positioned diagnostics
are remapped including position references embedded in the message body
(`previous declaration at gen.go:7:6` becomes `... at a.go:4`), autogenerated
diagnostics pass through, and any unpositioned message (`# p`, `go tool
compile: signal: killed`, a stray continuation) fails the remap. Every input
record remains in the result on failure, tagged `mapped`, `autogenerated`,
`unmapped`, `ambiguous`, or `unpositioned`, with its per-record error.

## 2. Exact diagnostic and multiplicity matcher

`annotations` reads `// ERROR "re" ...` lines with upstream errorcheck's
grammar (`GC_ERROR`, `ERRORAUTO`, `////` disables, `LINE±n` → `short:n`,
unquoted or uncompilable patterns are errors). Each quoted pattern is one
expected diagnostic.

Diagnostic regexps are whole-text anchored. A fixture that intentionally
allows surrounding text must express that with `.*`; a bare substring cannot
accidentally accept a different message. The mechanism also exposes exact
literal-text and whole-text regexp helpers.

`matchDiagnostics` computes a maximum one-to-one assignment between
annotations and remapped diagnostics (an annotation accepts a diagnostic only
on its own original file and line, or, for `ERRORAUTO`, only an
`<autogenerated>` diagnostic) and reports what is left on both sides. The
match is complete only when the assignment is perfect: one missing
diagnostic, one extra diagnostic, one duplicate absorbed by a single
annotation, one diagnostic that two annotations would both need, or an
`<autogenerated>` line without an `ERRORAUTO` annotation all fail.
Assignment is order-independent, so two annotations on one line are matched
whichever order the compiler printed them.

## 3. Exact byte matcher

`matchBytes(expected, observed)` compares whole byte strings with no
trimming or newline normalization and classifies a mismatch as `missing`
(observed truncated), `extra` (observed longer) or `differs`, with the first
differing offset. `A\n\nB\n` against `A\nB\n\n` differs at offset 2. The command
also accepts a byte-only request, so an exact or shared-sink ordered-byte
obligation needs no dummy map. Proving the observed file came from the shared
kernel sink remains the execution integrator's responsibility.

## Command contract

```sh
go -C tools/go-full/source-remap build -o source-remap .
source-remap < request.json > response.json   # exit 0 PASS, 1 FAIL, 2 malformed request
```

Request (unknown fields and trailing data are rejected; every file is
digest-checked initially and re-checked after successful adjudication):

```json
{
  "evidence_root": "/absolute/canonical/evidence/root",
  "units": [
    {
      "generated": {"path": "…/gen.go", "sha256": "…"},
      "short": "gen.go",
      "aliases": ["/build/x/gen.go"],
      "map": {"path": "…/gen.go.map", "sha256": "…"},
      "sources": [
        {"path": "…/a.go", "sha256": "…", "name": "dir/a.go", "short": "a.go", "aliases": []}
      ]
    }
  ],
  "output": [{"path": "…/stdout", "sha256": "…"}, {"path": "…/stderr", "sha256": "…"}],
  "expected_bytes": {"path": "…/expected.out", "sha256": "…"},
  "observed_bytes": {"path": "…/observed.out", "sha256": "…"}
}
```

Every input path must be absolute, remain below `evidence_root` after symlink
resolution, name a regular non-symlink file, and match its SHA-256. Lexical
and parent-symlink escapes fail closed. `name` is the lowerer's safe relative
source name in the map; `short` is the name used by
diagnostics and ERROR annotations (no path separators). `aliases` are
compile-time spellings rewritten to the short name with upstream's
`replacePrefix` before parsing; ambiguous aliases reject. Autogenerated
diagnostics are always retained and matched or reported unexpected. Whether a
recipe may ignore them belongs to Sprint 154 policy and is not a mechanism
switch. `expected_bytes`/`observed_bytes` are optional but must be supplied
together; they may be the sole obligation when `units` and `output` are empty.

Response: `verdict`, `reason`, `evidence_scope`
(`remapped-original-position-diagnostics-and-exact-bytes-only`),
`validated_maps`, every `remapped_diagnostics` entry with its original
position metadata, the `diagnostic_match` (expected/observed/matched counts,
pairs, missing annotations, extra diagnostics) and, when requested, the
`byte_match`. `PASS` requires every map valid, every diagnostic remapped, a
perfect diagnostic assignment and equal bytes. A `PASS` here says the
retained output matches the original annotations exactly; process state,
receipts and recipe applicability are adjudicated by the caller.

## Verification

```sh
GOMAXPROCS=1 GOTOOLCHAIN=local /absolute/pinned/sdk/bin/go -C tools/go-full/source-remap vet ./...
GOMAXPROCS=1 GOTOOLCHAIN=local /absolute/pinned/sdk/bin/go -C tools/go-full/source-remap test -p=1 -count=1 ./...
```

The tests cover the retained product map and its mutation matrix, the empty
two-source package map, the marker contract, remapper ambiguity, all-or-
nothing failure with retained records, verified claims and embedded
references, exact multiplicity (order independence, missing, extra, absorbed
duplicate, one-for-two), anchored and explicitly permissive regexps, the
annotation grammar, `ERRORAUTO`, exact and ordered bytes, and the command end
to end (including digest tamper, lexical/symlink escape, aliases, byte-only
use, and request hygiene).
