## Failure priorities

1. **Source-map contract: all 85 compiled attempts.** Every transpile executes,
   but the map is refused before native build/run. In row 000, generated line 6
   is `// lower:19`, line 7 is a newly inserted `//line .../arrays.go:10:1`
   directive, and line 8 is the function declaration. The map records line 8;
   the existing strict next-nonempty-line marker contract requires line 7.
   The source map and generated bytes are retained exactly. The frozen candidate
   and validator were not modified during this replay.
2. **Collections and native scalar/aggregate transfer.** String-to-`[]byte`
   conversions fail in five rows. Native byte slices are treated as scalars in
   embed, JSON, reading-files and spawning-processes. Nil slices, composite
   assignment/range and named map keys remain unsupported in other rows.
3. **Callables and native type boundaries.** Function literals, handler values,
   imported generic `errors.AsType`/`slices.Sort`/`SortFunc`, local named values
   such as `rect`/`person`/`Plant`, native pointer methods/fields, tuple assignment
   and nested receivers account for further failures. The exact paths and
   diagnostics are indexed in the retained failure records.
4. **Native channels and task state.** `time.After`, `timer.C`, `ctx.Done`,
   limiter channels and native handles in task snapshots still fail; passing
   basic channel rows do not cover these combinations.
5. **Observable environment and scheduling.** The interpreter exposes extra
   shell/agent environment keys despite the same supplied runtime environment.
   `closing-channels` emits the same nine events in a different legal order;
   its reviewed classification currently allows no normalization, so that row
   remains a mismatch. Neither difference was normalized away in this run.
6. **Testing driver callback.** Canonical multifile `-- -test.v` now reaches the
   separate driver, then fails at its `gbeMatchString` callback. The original
   `_test.go` remains unchanged. Passing the selected-original-test API's
   focused tests does not certify this standalone driver path.
